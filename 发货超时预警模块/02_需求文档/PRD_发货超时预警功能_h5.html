📦 发货超时预警功能 PRD

📌 v2.2 👤 产品经理 📅 2026-08-11 ⏳ 待研发交接

帮助跟单员及时处理即将超时的待发货订单，通过按商品类型分档预警、分级 ActionCard 通知、处理记录等功能，降低订单超时发货率。

1. 背景与目标

1.1 背景

跟单员每天处理大量待发货订单，靠人工巡查哪些即将超时，效率低、容易遗漏。超时后才被发现，错过最佳处理时机。

现有后台能力：
  • 已有「待发货列表」，含 待发货/已超时/今日发货 三个Tab
  • 仓库和跟单员都在同一个钉钉群
现有不足：
  • 没有预警通知，靠人工巡查
  • 没有分级风险标识
  • 没有超时处理记录

1.2 上线后影响

超时发货率
↓ 下降
客户投诉率
↓ 下降
处理效率
↑ 提升

1.3 目标（v2.0 重构）

  1. 按商品类型分档预警：铸件/非标件=预计发货日；标准件-库存=订单创建+1天；标准件-PO采购=PO 订单供应商交期；软件订单不进入预警池（付款后自动发邮箱，状态=已发货）
  2. 分级处理：按剩余时间分为4级，红色紧急优先
  3. 钉钉通知（统一一套）：4 级 ActionCard 卡片，emoji 区分等级，合并规则按等级生效；取消"提前催办"双轨机制
  4. 交期管理：待发货 Tab 提供"修改交期"入口（走审核列表模块），本 PRD 不重复开发弹窗/审批

2. 用户角色与故事

角色身份用户故事
跟单员负责跟单的人员想要<看到哪些订单即将超时>，以便<优先处理紧急订单>
仓库人员仓库打包发货想要<实时知道哪些单需要优先发货>，以便<提前准备货物>
商家管理员老板/主管想要<掌握整体超时风险>，以便<监控团队情况>

3.2 风险等级预警（v2.0 按商品类型分档）

🎯 核心变化：预警基准从 2 类扩展到 5 类（软件不进池）

基准一览

🔧 铸件
基准 = 预计发货日（供应商交期+客户交期共同确定，可通过"修改交期"调整）
🛠️ 非标件
基准 = 预计发货日（兜底方案；TODO 待业务确认是否按"委外/现货"细分）
📦 标准件-库存件
基准 = 订单创建时间 + 1 天（无PO订单即视为库存件）
📑 标准件-PO采购
基准 = PO 订单供应商交期（有PO订单即用对应PO的应到货日）
💿 软件
不进入预警池（付款后自动发邮箱，状态=已发货）
⚠️ 铸件/非标件无交期时的兜底规则（v2.1 补充）：客户交期/供应商交期必须填写，若未填写则暂按"订单创建+7天"兜底计算；跟单员补录交期后，系统自动切换回正常的"预计发货日"基准，重新计算剩余时间和风险等级。

风险等级定义

≤2h
🚨 紧急
2-8h
⚠️ 高风险
8-12h
⏰ 中风险
12-72h
📋 低风险
>72h
— 无需提醒

提醒时间点

剩余时间 ≤ 72小时（3天）：开始提醒

通知触发时机（与等级入口对齐）：12小时（进入中风险）、8小时（进入高风险）、2小时（进入紧急）

v2.0 删除 4h 触发点：4h 落在高风险(2-8h)区间内，非等级入口，v2.0 统一机制下不再单独触发通知，该时间点为 v1.x 提前催办机制残留。

升级规则

状态单向升级：低 → 中 → 高 → 紧急（不可回落） 每等级只通知1次，不重复打扰 超时后移入「已超时」Tab，不再触发新等级预警
修改交期后的处理：
  • 以新基准（预计发货日/PO交期）重新起算剩余时间
  • 等级可降低（允许从高等级回落至低等级）
  • 已发送的通知记录清零，按新基准重新触发各等级通知
  • 已超时订单：若新剩余时间>72h，自动从「已超时 Tab」流回「待发货 Tab」

已超时Tab排序规则

第1排序（绝对优先）：按逾期时长降序（超时越久越靠前） 第2排序（同逾期时长时）：按处理状态（待处理 > 处理中） 注：第1排序绝对优先，处理状态仅在逾期时长完全相同时作为次要参考

3.3 钉钉群通知（v2.0 统一一套机制）

🔔 重要变更：v1.x 的"提前催办"双轨机制已移除，只保留一套基于剩余时间触发的钉钉群通知。所有等级均使用同一种 ActionCard 卡片，emoji 区分等级（钉钉机器人不支持设置卡片背景色）。
等级emoji合并规则@策略
🚨 紧急🚨不合并，逐条发送不@
⚠️ 高风险⚠️按跟单员合并不@
⏰ 中风险⏰按仓库合并不@
📋 低风险📋全部合并1条不@
升级衔接：单向升级（低→中→高→紧急），每等级只发1次，升级到新等级时按新等级的合并规则重新发。同等级内不重复推送。修改交期后等级可回落，已发通知记录清零重新积累。

4. 核心流程

4.1 系统预警流程

定时任务启动(每60分钟) ↓ 查询待发货订单（软件订单已自动发货，不在池中） ↓ 按商品类型分档确定基准： 铸件 → 预计发货日 非标件 → 预计发货日（兜底） 标准件-有PO → PO 订单供应商交期 标准件-无PO → 订单创建+1天 软件 → 跳过 ↓ 计算剩余时间 = 基准 - 当前时间 ↓ ┌─────────────────────────────┐ │ 剩余时间 ≤ 72h?（在预警范围内）│ │ └─ ≤ 2h? → 🚨紧急 │ │ └─ ≤ 8h? → ⚠️高风险 │ │ └─ ≤ 12h? → ⏰中风险 │ │ └─ ≤ 72h? → 📋低风险 │ │ 否则 → 无预警 │ └─────────────────────────────┘ ↓ 该等级已通知过? → 跳过通知 ↓ 未通知 → 发送钉钉 ActionCard → 记录notified_levels ↓ 更新列表显示
⚠️ 补充说明（v2.1）：流程图里"铸件"/"非标件"分支的基准都写"预计发货日"，但这个基准来自客户/供应商交期，交期没填的情况下走§3.2.2的兜底规则——暂按"订单创建+7天"计算，等跟单员补录交期后系统自动切换回正常规则。实现时这两个分支要加一个"有没有交期"的判断，没有交期时走兜底基准，避免漏掉这条分支。

4.2 订单发货完整生命周期（v2.0）

订单创建 （基准按商品类型分档；铸件/非标件=预计发货日，标准件-库存=订单创建+1天，标准件-PO采购=PO 交期；软件→已发货，不进池） │ ▼ 系统定时扫描（每60分钟，软件订单跳过） │ ▼ T-72h（距基准72小时）────── 📋 低风险预警开始 │ ▼ T-12h ──────────────────── ⏰ 中风险预警 │ ▼ T-8h ───────────────────── ⚠️ 高风险预警 │ ▼ T-2h ───────────────────── 🚨 紧急预警 │ ▼ T+0（基准到期）──────────── 移入「已超时Tab - 待处理」 │ ▼ 跟单员处理 ├── 点击「发货」→ 状态校验 → 确认发货 → 订单从列表消失 ├── 点击「标记处理」→ 选择原因 → 处理中 → 后续点击「发货」→ 订单从列表消失 └── 点击「修改交期」→ 跳转审核列表 → 通过后新交期剩余时间>72h → 自动流回待发货 Tab（重新积累通知）
