1. 背景与目标

1.1 背景

启泰数智模具配件 B2B 商城，财务模块长期存在 3 个问题：

  1. 资金流水 vs 收支明细混淆——历史做法是把"订单列表"硬塞进收支明细页，待支付、已取消的订单都列出来，最后对账对不上。
  2. 销售统计口径不统一——铸件是定制品（按客户来图时间组织生产），标准件是现货（按支付时间算），但旧系统一律按"订单创建时间"统计，账期客户差异巨大。
  3. 坏账没有管理路径——账期客户到期未还款，过去只能人工 Excel 标记，销售总额虚高，无法反映真实回款。

1.2 上线后影响

  • 财务对账准确率从约 70% 提升到 95%+
  • 销售统计支持"按支付时间/来图时间"双口径，铸件销售时点判断更准
  • 坏账独立标记，老板看报表不被虚高数字误导
  • 退款失败可追踪可重试，减少资金风险

1.3 目标

#目标衡量指标
1收支明细页只展示"钱真发生过"的事件待支付/已取消订单不出现
2销售统计支持 4 维度 + 铸件双时间口径按时间/客户/商品/支付方式/渠道均可拆分
3坏账有独立状态机和操作路径财务可手动勾销，销售总额自动剔除

2. 用户角色与故事

角色身份用户故事
财务启泰财务岗位查看每笔收支 → 客户取消的退款能跟踪到原支付单 → 账期坏账手动勾销
销售启泰销售/销售管理按客户/渠道看销售排行 → 铸件按来图时间看真实需求 → 客户取消的订单可追溯
运营/管理层启泰运营 + 老板看本月净销售（含坏账剔除）→ 按商品分类看各品类销售 → 异常退款快速定位
研发启泰研发 + DBA30 字段 7 组清晰建模 → 状态机可测试 → 统计公式可 SQL 复现

3. 功能需求

3.1 模块一：资金流水（fund_flow）

3.1.1 功能描述

展示每一笔"钱真实发生过"的事件，待支付、已取消的订单不计入。收支明细页是商家最常用的对账入口。

3.2 模块二：销售统计

3.2.1 功能描述

聚合视图，不落表，实时从 fund_flow SELECT GROUP BY 计算。按 4 个维度拆分统计，支持铸件的双时间口径切换。

3.2.2 统计维度（4 个）

维度维度值备注
按时间2026-07 / 2026-W28 / 2026-07-13 等默认按"支付时间"；铸件可切"来图时间"
按客户客户名
按商品分类全部（标准件+铸件+软件）/ 标准件 / 铸件 / 软件 / 其他"全部" = 3 类合计
按支付方式在线支付 / 账期支付 / 线下打款
按渠道小程序端 / PC端 / 线下

3.2.3 时间口径（铸件特殊）

口径字段适用分类用途
支付时间（默认）fund_time全部财务对账、销售入账统计
客户来图时间order.drawing_received_at仅铸件销售订单需求时点统计

切换"来图时间"时：标准件/软件仍按 fund_time 统计（不可切换）；铸件改按 drawing_received_at 统计。

⚠️ 风险提示（2026-08-08）：order.drawing_received_at 字段是否已存在于订单表，§8.2标注"待确认"。这条口径切换功能和对应的验收标准目前当作已确定功能在描述，实际是否能实现取决于这个字段存不存在，评审时需要向研发确认，不要当成已落地功能对待。

3.2.4 汇总卡（4 张）

卡片公式
销售总额SUM(amount WHERE direction=income AND fund_status=received)
退款总额SUM(amount WHERE direction=expense AND fund_status=refunded)
坏账金额SUM(amount WHERE direction=income AND fund_status=bad_debt)
净销售额销售总额 - 退款总额（坏账已通过fund_status=received的筛选条件被排除，不需要在这里再减一次；2026-08-08修正：原公式"销售总额-退款总额-坏账金额"重复扣减了坏账，导致净销售额被低估）

3.2.5 列表字段（6 列）

#字段公式
1维度值GROUP BY 的 key
2销售订单数COUNT(DISTINCT order_id WHERE direction=income AND fund_status=received)
3销售总额同汇总卡
4退款笔数COUNT(* WHERE direction=expense AND fund_status=refunded)
5退款总额同汇总卡
6净销售额销售总额 - 退款总额（同§3.2.4修正，坏账不重复扣减）

最后一行"合计"汇总所有维度行。

3.2.6 规则约束

  • 销售总额只算 received 的钱，不包含 pending / reversed / bad_debt
  • 退款总额只算 refunded 的，不包含 failed / pending
  • 部分退款的订单按 1 笔算，金额按实际退款算
  • 全额退款的订单：原收入改 reversed，新支出记 refunded，不计入销售总额

3.2.7 异常情况

场景处理方式
铸件无来图时间（标准件/软件订单）不可切换到"来图时间"维度，仅"支付时间"
维度切换后某分类无数据显示空状态"暂无符合条件的数据"
切换时间口径后总数变化顶部汇总卡实时更新，列表同步刷新

3.3.1 功能描述

聚焦"钱出去了"的所有记录。展示所有退款的明细，区分 4 种退款类型 × 4 种退款状态。

3.3.2 列表字段（11 列）

#字段展示来源
1退款单号蓝色 monorefund_id（关联）
2退款时间时间降序refund_time
3退款类型4 色 pillrefund_type
4退款状态4 色 pillfund_status
5退款金额红色，右对齐amount + direction=expense
6原支付金额灰色，参考用原 payment.amount
7关联原订单蓝色 mono，跳转order_id
8原支付方式彩色 pill原 pay_method
9客户/企业文本customer_name
10退款原因客户填的或系统生成remark
11操作详情 / 重试 / 催促—

3.3.3 退款类型（4 种）

枚举值中文触发场景
cancel_paid客户取消已支付订单客户在订单未发货前取消，自动触发
refund_partial售后部分退款售后申请部分商品退款
refund_full售后全额退款售后申请全部商品退款
adjustment平台/财务调账财务手动补差

3.3.4 退款状态（4 种）

枚举值中文含义
pending待退款退款单创建，等待通道处理
processing退款中通道处理中
refunded已退款退款成功
failed退款失败通道返回失败，需人工重试

3.3.5 汇总卡（4 张）

卡片公式
退款总额SUM(amount WHERE direction=expense AND fund_status=refunded)
待处理COUNT(* WHERE direction=expense AND fund_status IN (pending, processing))
退款失败COUNT(* WHERE direction=expense AND fund_status=failed)
涉及订单数COUNT(DISTINCT order_id WHERE direction=expense)

3.3.6 规则约束

  • 部分退款：原 payment_id 关联的收入记录不修改，只新增一条支出流水
  • 全额退款：原收入记录 fund_status 改 reversed，同时新增一条支出 refunded
  • 退款失败可点击"重新退款"重试，成功后状态置 refunded
  • 退款原因必填（客户填的或系统自动）

3.3.7 异常情况

场景处理方式
退款失败操作栏显示"重新退款"按钮，财务可手动重试
平台调账退款refund_type=adjustment，退款原因填"调账-补差"等
多次部分退款每笔退款单独立存在，按时间倒序排列

4. 核心流程

4.1 资金流水触发规则（关键）

订单创建（待支付） → ❌ 不记流水 订单创建（已支付） → ❌ 不记流水 支付成功（在线） → ✅ income / received 支付成功（线下，审核通过）→ ✅ income / received 账期支付 - 客户实际打款 → ✅ income / received 订单取消（未支付） → ❌ 不记流水 订单取消（已支付） → ✅ expense / refunded 售后部分退款 → ✅ expense / refunded（原收入记录不改） 售后全额退款 → ✅ expense / refunded + 原收入 → reversed 财务调账（补收） → ✅ income / received 财务调账（补退） → ✅ expense / refunded 坏账勾销（账期到期） → ✏️ income: received → bad_debt（财务直接做，无审批） 催收回款（坏账已勾销后）→ ✅ 新建 income / received（不挂原支付单）

4.2 坏账勾销流程

账期 30 天到期 → 客户未还 → 财务点击「坏账勾销」按钮 ↓ fund_flow: fund_status = received → bad_debt remark = "已坏账勾销 by 财务XXX" + 时间戳 ↓ 销售统计：销售总额自动剔除该笔 → 进入"坏账金额"卡

关键决策：

  • 账期 30 天到期即可勾销
  • 不需审批，财务直接做
  • 勾销后不可逆（除非走特殊恢复流程，留痕）

4.3 部分退款流程

客户申请售后部分退款 ↓ 创建 refund 记录，refund_type = refund_partial ↓ 创建支出流水：direction=expense, fund_status=refunded amount = 本次退款金额（原收入记录不改） ↓ 统计：销售总额 = SUM(received) - 不变 退款总额 += 本次退款金额 净销售额 = 销售 - 退款（坏账不重复扣减，见§3.2.4）

为什么不改原收入？ 对账时要找到原始入账金额，原记录 + 后续支出记录可推算净额。

5.1 资金流水表 fund_flow

详见 3.1.2 字段说明。

唯一索引：

7. 验收标准

7.1 资金流水验收

  • 待支付、已取消的订单不出现在收支明细页
  • 列表展示 9 列字段，与原型一致
  • "仅收入/仅支出" Tab 切换正确
  • 导出 Excel 按当前筛选条件
  • 流水编号格式 LSyyyymmddXXXXX 唯一

7.2 销售统计验收

  • 4 个维度（按时间/客户/商品分类/支付方式/渠道）切换正常
  • 铸件可切换"支付时间/来图时间"双口径，标准件/软件不可切换
  • "全部" = 标准件 + 铸件 + 软件 三类汇总
  • 坏账金额从销售总额中剔除，不重复计入
  • 净销售额 = 销售总额 - 退款总额（坏账不重复扣减，见§3.2.4修正说明）
  • 最后一行"合计"汇总所有维度行

7.3 支出统计验收

  • 11 列字段展示与原型一致
  • 4 种退款类型 × 4 种退款状态 全部覆盖
  • 退款失败显示"重新退款"按钮
  • 部分退款时原收入记录不变
  • 退款原因必填

7.4 数据一致性验收

  • 同一订单的"部分退款"产生独立的支出流水，原收入记录 fund_status 保持 received
  • 同一订单的"全额退款"产生一条支出 + 原收入改 reversed
  • 账期客户实际打款才产生 received 流水，账期台账扣减额度同步
  • 坏账勾销后销售统计自动剔除该笔
  • 催收回款新建独立 received 流水，不挂回原支付单
