字段字典（7 组 / 30 个）
状态枚举
统计公式
数据库表 fund_flow 全部字段，按 7 组分类。 * = 必填 / ○ = 可选 / KEY = 主键
① 核心标识 主键 / 业务单据号
字段名中文名类型必填含义 / 取值
flow_id流水IDbigintKEY数据库主键，自增
flow_no流水编号string(20)*业务可读。规则：LS + yyyymmdd + 序号，如 LS20260711001
② 资金信息 钱本身
字段名中文名类型必填含义 / 取值
direction资金方向enum*income 收入 / expense 支出（退款）
flow_type资金类型enum*order_payment 订单收款 / order_refund 订单退款 / adjustment 调账
amount金额decimal(15,2)*永远正数，方向靠 direction 字段
currency货币string(8)○默认 CNY（人民币）
fee手续费decimal(15,2)○如支付宝提现费、退款手续费
actual_amount实际到账decimal(15,2)○= amount - fee。一般等于 amount，除非扣手续费
③ 关联实体 连出去追溯
字段名中文名类型必填含义 / 取值
order_id关联订单号string(20)*一笔流水一定挂着一个订单
payment_id关联支付单号string(20)*收入时填本笔支付单；支出时填原支付单（不是新生成的）
refund_id关联退款单号string(20)○仅 direction=expense 时填，收入时为空
settlement_id关联结算单号string(20)○已纳入某期结算时挂上
statement_id关联对账单号string(20)○对账后挂上
④ 业务维度 GROUP BY 字段 · 销售统计用
字段名中文名类型必填含义 / 取值
customer_id客户IDstring(20)*客户主数据 ID
customer_name客户名称string(100)*冗余存储，列表展示不用 JOIN
sku_id商品/SKU IDstring(20)○商品主数据 ID
sku_name商品名称string(100)○冗余存储
category商品分类enum*standard 标准件 / casting 铸件 / software 软件 / other 其他
channel订单来源渠道enum*miniprogram 小程序端 / pc PC端 / offline 线下
pay_method支付方式enum*online 在线支付（支付宝+微信）/ credit_period 账期支付 / offline 线下打款
⑤ 时间字段 对账必备 · 4 个时间维度
字段名中文名类型必填含义 / 取值
biz_time业务时间datetime*订单创建时间
pay_time支付时间datetime*客户付了款的时间
fund_time入账时间datetime*钱实际到账。在线支付 ≈ pay_time；线下打款 = 财务审核通过时间；账期 = 客户实际打款时间
refund_time退款时间datetime○仅 direction=expense 时填
⑥ 状态字段 资金状态 / 对账状态
字段名中文名类型必填含义 / 取值
fund_status资金状态enum*5 个值：received 已入账 / reversed 已冲销 / bad_debt 坏账 / refunded 已退款 / failed 退款失败
reconcile_status对账状态enum○unreconciled 未对账 / matched 已匹配 / abnormal 异常（需人工介入）
⑦ 审计字段 谁在什么时候建的
字段名中文名类型必填含义 / 取值
created_by创建人string(50)○系统自动生成则填 system
created_at创建时间datetime*流水记录创建时间（≠ 入账时间）
updated_by修改人string(50)○最后修改人
updated_at修改时间datetime*最后修改时间
remark备注string(500)○调账时必填原因；坏账时记"已坏账勾销 by 财务XXX"

订单状态 → 资金动作 映射

业务事件记流水？方向金额资金状态
订单创建（待支付）❌ 不记——钱没动
支付成功（在线：支付宝/微信）✅ 记一笔收入实付金额received
支付成功（线下，财务审核通过）✅ 记一笔收入实付金额received
账期支付 - 客户实际打款✅ 记一笔收入实付金额received
订单取消（未支付）❌ 不记——钱没动
订单取消（已支付）✅ 记一笔支出原支付金额refunded
部分退款（售后）✅ 记一笔支出本次退款金额refunded
全额退款（售后）✅ 记一笔支出原支付金额refunded
财务调账（补收/补退）✅ 记一笔收入/支出调账金额received / reversed
坏账勾销（账期到期未还）✏️ 修改收入—received → bad_debt
关键点：部分退款时，原支付那笔收入记录不改，只新增一条支出流水。两行并存，统计时 SUM(收入) - SUM(支出) 就拿到净收入。 不要在原记录上做"净额"计算，否则对账时找不到原始入账金额。

其他枚举值

商品分类（category）
  • standard 标准件（现货）
  • casting 铸件（定制，双时间口径）
  • software 软件（虚拟商品）
  • other 其他
渠道（channel）
  • miniprogram 小程序端
  • pc PC端
  • offline 线下
支付方式（pay_method）
  • online 在线支付（支付宝 + 微信）
  • credit_period 账期支付（到期结算才入账）
  • offline 线下打款（财务审核通过才入账）
资金类型（flow_type）
  • order_payment 订单收款
  • order_refund 订单退款
  • adjustment 财务调账
退款类型（refund_type）
  • cancel_paid 客户取消已支付订单
  • refund_partial 售后部分退款
  • refund_full 售后全额退款
  • adjustment 平台/财务调账
对账状态（reconcile_status）
  • unreconciled 未对账
  • matched 已匹配
  • abnormal 异常（人工介入）

销售统计公式（基于资金流水实时聚合）

销售总额
SUM(amount WHERE direction=income AND fund_status=received)
只算已入账的钱，剔除坏账
坏账金额
SUM(amount WHERE direction=income AND fund_status=bad_debt)
账期到期未还 + 财务已勾销
退款总额
SUM(amount WHERE direction=expense AND fund_status=refunded)
只算已退款成功的，failed/pending 不算
⭐ 净销售额
销售总额 - 退款总额 - 坏账金额
老板最该看的数字
成交订单数
COUNT(DISTINCT order_id WHERE direction=income AND fund_status=received)
按 order_id 去重

销售统计 - 时间口径（铸件特殊）

支付时间（默认）
fund_time
钱实际到账的时间。用于：财务对账、销售入账统计
适用：标准件 / 软件 / 铸件（入账视角）
客户来图时间（铸件专用）
order.drawing_received_at
铸件客户提交图纸的时间。用于：销售订单需求时点统计
适用：仅铸件

支出统计公式

退款总额
SUM(amount WHERE direction=expense AND fund_status=refunded)
只算已退款成功的
退款笔数
COUNT(* WHERE direction=expense)
含待退款/失败/成功所有状态
涉及订单数
COUNT(DISTINCT order_id WHERE direction=expense)
按 order_id 去重
特别说明：
  1. 所有 amount 字段都是正数，方向靠 direction 区分
  2. 「待支付」订单不进入资金流水
  3. 账期支付 = 客户实际打款才入账
  4. 线下打款 = 财务审核通过才入账
  5. 坏账勾销 = 账期 30 天到期 + 财务手动操作，不需要审批
  6. 催收回款 = 新建一条 received 流水，不挂回原支付单
  7. 部分退款 = 原收入记录不改，只新增一条支出流水
